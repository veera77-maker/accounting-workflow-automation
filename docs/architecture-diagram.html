STAGE B Deterministic Decision Pipeline

High-trust, low-cost deterministic calculations. No LLM or ML models are used where explicit rules and statistical checks provide deterministic, auditable decisions.

Reconciliation Rules
Matches expense records against receipts using normalized vendor strings (strips corporate suffixes) and ±$0.01 tolerance comparison.
Verdicts: EXACT_MATCH · AMOUNT_MISMATCH · VENDOR_MISMATCH · MISSING_RECEIPT
↓ Reconciled dataset feeds categorization
Categorization Rules
Assigns standard 7-category taxonomy using deterministic vendor lookup, fuzzy vendor matching where applicable, and fallback keyword matching.
Taxonomy: Travel, Meals, Software, Supplies, Utilities, Marketing, Professional Services (No ML model used)
↓ Categorized records feed anomaly detection
Anomaly Detection Rules + Statistical
Scans categorized expenses for policy violations and statistical outliers. Determines routing verdict (NORMAL vs. REVIEW).
Implemented Signals: HIGH_VALUE (category mean × 3.0, with minimum sample threshold) · DUPLICATE (hash match) · NEW_VENDOR (lookup) · RECONCILIATION_MISMATCH

STAGE D Accounting Engine

Deterministic ledger posting and aggregation. Financial statements are derived strictly from posted ledger records.

Ledger Rules + Tools

Pure deterministic arithmetic: Sum(Line Items) == Total · Financial Source of Truth

Technical Scope & Empirical Disclaimers
  • Latency Measurement: 10.822 ms is a local prototype measurement on synthetic data using ThreadPoolExecutor, NOT production latency. Production latency will depend on database transit, network overhead, and real data volumes.
  • LLM Cost: The prototype utilizes FakeLLMClient and makes zero external API calls ($0 external spend). Production LLM cost has not been measured and will depend on provider token pricing and caching.
  • Dataset Scope: This is a local engineering prototype using synthetic accounting datasets. It does not represent production deployment, production cost, customer validation, or ROI claims.
  • Receipt Processing (OCR Boundary): The current prototype processes structured JSON receipt data. Real OCR is a future integration boundary and is NOT implemented.
  • Categorization Implementation: Implemented via deterministic vendor table lookup and keyword rules. There is NO trained ML categorization model in this artifact.
  • Anomaly Signals: Explicitly implements four deterministic/statistical signals: HIGH_VALUE (category mean × 3.0, with minimum sample threshold), DUPLICATE, NEW_VENDOR, and RECONCILIATION_MISMATCH.
